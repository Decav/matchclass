## 1. Contexto y Problema

El repositorio contiene únicamente documentación (skills de arquitectura, documento técnico y comercial). No existe código ejecutable: no hay `package.json`, ni build, ni forma de levantar nada. Ningún RC posterior puede implementarse hasta que exista el esqueleto del proyecto con su toolchain configurado.

## 2. Objetivo

Dejar un proyecto React 19 + TypeScript + Vite que arranca en local, con Firebase (Auth + Firestore) configurado contra emuladores, la estructura de directorios de las 4 capas NDK, los aliases de path funcionando, y las herramientas de calidad (TypeScript strict, ESLint, Prettier) sin errores.

Al cerrar este RC, un desarrollador clona, corre `npm install && npm run dev`, y ve la aplicación.

## 10. Notas

**Alcance deliberadamente vacío de UI.** Este RC no implementa el design system (RC-002) ni pantallas de producto. La vista que se renderiza es una pantalla de verificación técnica, pensada para ser reemplazada por RC-002/RC-007.

**Sin MSW.** El seed original lo incluía para mockear REST. Con Firestore como fuente de datos, el rol de MSW lo cumplen los emuladores. Se difiere hasta que exista una API HTTP auxiliar que lo justifique.

**Sin Sentry en este RC.** Requiere un DSN de un proyecto que aún no existe. La variable queda declarada en `.env.example` como opcional.

**Versión de Node — resuelto.** El entorno local tenía Node 20.17.0, por debajo del mínimo de Vite 8 (`^20.19.0 || >=22.12.0`). Se instaló Node 22.23.1 vía nvm y se fijó `22` en `.nvmrc` más `engines` en `package.json`. Quien clone con una versión menor recibe un aviso de npm al instalar.

**Validación de entorno en el arranque.** Las claves web de Firebase son públicas, pero su ausencia debe fallar ruidosamente: sin `projectId` el SDK inicializa igual y revienta más tarde con un error de red que no señala la causa.

## 11. Registro de implementación

Decisiones tomadas durante la ejecución que no estaban en el alcance original:

| Decisión | Motivo |
|---|---|
| ESLint 9 + typescript-eslint en vez de oxlint | El scaffold actual de Vite trae oxlint, pero las reglas de frontera entre capas NDK (`no-restricted-imports`) y las reglas *type-aware* que prohíben `any` y promesas flotantes requieren typescript-eslint. |
| `eslint-plugin-react-hooks` vía `configs.flat['recommended-latest']` | En la v7 el export `configs['recommended-latest']` sigue siendo formato eslintrc y ESLint 9 lo rechaza al arrancar. |
| `@eslint/js` fijado en la major 9 | `@eslint/js@10` exige ESLint 10 como peer y rompe la instalación. |
| TypeScript 5.9.3 (no 6 ni 7) | Es la versión que documenta el stack y la soportada oficialmente por typescript-eslint 8. Subir a TS 6/7 es una decisión aparte. |
| Sin `src/resources/constants/usm-schedule.ts` | Fuera del alcance de infraestructura, y el rango de bloques del tech-document tiene una contradicción sin resolver (ver Notas). |
| `strict: true` explícito en `tsconfig.app.json` | El scaffold de Vite ya no lo incluye. La regla "sin `any`" del proyecto lo exige. |

**Vulnerabilidades aceptadas** (`npm audit` reporta 7 *high*, todas de dos raíces):

| Aviso | Decisión |
|---|---|
| `react-router` — CSRF bypass en modo RSC (GHSA-qwww-vcr4-c8h2) | **No aplica.** MatchClass es una SPA cliente sin React Server Components ni server actions. El único "fix" que ofrece npm es bajar a 7.11.0, perdiendo siete versiones de correcciones. |
| `brace-expansion` — DoS por expansión no acotada | **Aceptada.** Llega como transitiva de `eslint → minimatch@3`; no existe parche en la línea 1.x y forzar la 5.x rompería minimatch. Es dev-only y los globs afectados los escribimos nosotros en `eslint.config.js`: no hay entrada controlable por terceros. |

Revisar ambas cuando haya versiones nuevas de `react-router` y `eslint`.
